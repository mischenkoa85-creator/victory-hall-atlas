are resolved from --session-sql-dir.parent by the runner. No Windows source path is

Linux invocation (operator supplies the reviewed Python environment):
python -u -B operations/tests/test_warehouse_pg.py \
  --pg-bin /usr/lib/postgresql/17/bin \
  --session-sql-dir /absolute/bundle/session/sql \
  --output /short/new/private/path \
  --http-check --board-http-check

Run under an unprivileged dedicated OS user (initdb rejects root). Output must not
exist. Runner creates output and socket directory with mode0700; data directory is
created by initdb. Linux uses ONLY that Unix socket, listen_addresses='', and checks
inet_server_addr() IS NULL. There is no TCP listener and no public HTTP listener.
Keep the output path short enough for Unix socket filenames (runner checks <100 bytes).

Windows default stays loopback127.0.0.1 on a fresh free port, executables with .exe.
Linux executables have no .exe suffix. Runtime fsync must remain on and is asserted.
--fast-initdb is optional for disposable fixtures only: skips initdb final sync,
never runtime fsync. Do not use it as evidence of crash durability.

The runner refuses an existing output directory, creates warehouse_synthetic in the
NEW cluster, installs actual session-core SQL, warehouse and board candidate SQL,
and seeds only synthetic identities, capabilities, categories and records. It does
not connect to GREEN or any existing database. Finally it stops the same new cluster.

Outputs: RESULT.json; HTTP_SQL_RESULT.json when --http-check;
BOARD_SQL_RESULT.json and BOARD_HTTP_SQL_RESULT.json when --board-http-check.
These verify application transactions/authorization, not production migration,
physical crash durability, real login, real uploaded-file ownership or browser UI.

Attachment verification in board_http_pg_check.py is an explicit synthetic registry.
It is test-only. board_api.py has no default verifier: completion fails closed503
without a trusted attachment-store dependency, and client hash/MIME fields are forbidden.
